# 動作を軽くする・書き出しを速くする

「編集が遅い」の相談は、操作の問題ではなく**再生が重い**ことが原因のケースが多い。以下の順に切り分ける。

## 1. 切り分けの順番

1. 素材のコーデックは何か（H.264/H.265 の長尺 GOP、10bit 4:2:2、4K/8K、可変フレームレート＝VFR は重い）
2. タイムライン解像度とプロキシ設定は適切か
3. レンダーキャッシュは効いているか
4. GPU / メモリ設定は妥当か
5. その上で、素材そのものを軽い形式に変換するか

## 2. まず試す（すぐ効く順）

### タイムラインプロキシ解像度
`Playback`（再生）メニュー → **Timeline Proxy Resolution** → `Half` / `Quarter`
再生用に間引くだけなので**書き出し品質には影響しない**。一番手軽で効果が大きい。

### レンダーキャッシュ
`Playback` メニュー → **Render Cache** → `Smart` または `User`
- `Smart`: Resolve が重いと判断した箇所（エフェクト、合成、Fusion）を自動でキャッシュ
- `User`: 自分で指定した範囲だけキャッシュ
- キャッシュ形式は `プロジェクト設定 → Master Settings → Optimized Media and Render Cache` で指定（DNxHR / ProRes 系が扱いやすい）

### 最適化メディア（Optimized Media）
メディアプールでクリップを選択 → 右クリック → **Generate Optimized Media**
編集しやすい中間コーデックに変換したファイルを裏で作り、再生時にそちらを使う。
H.264/H.265 の長尺素材（スマホ・ミラーレスの動画、画面収録）で劇的に軽くなる。

### プロキシメディア（Proxy Media）
右クリック → **Generate Proxy Media**。最適化メディアより軽い代理ファイル。
外部で作ったプロキシをリンクすることもできる（`Link Proxy Media`）。

> 最適化メディア / プロキシ / レンダーキャッシュは**生成にディスク容量を食う**。
> 保存先は `プロジェクト設定 → Master Settings → Working Folders` で確認・変更する。速い SSD を指定する。

## 3. 環境設定側

- `環境設定 → Memory and GPU`: GPU 処理モード（CUDA / OpenCL / Metal / Auto）と使用 GPU の選択。
- `環境設定 → Media Storage`: キャッシュ用のスクラッチディスクを高速ドライブに。
- **可変フレームレート（VFR）素材**は同期ズレと重さの温床。スマホや画面収録の素材は、事前に固定フレームレートへ変換しておくと後工程が全部楽になる。

## 4. 書き出し（Deliver ページ）

- 納品先ごとの **レンダープリセット** を作って保存する（プリセット欄の `…` → `Save As New Preset`）。
- YouTube / Vimeo などのプリセットは用意されているが、ビットレートは案件に合わせて上書きしてよい。
- **レンダーキューに複数ジョブを積んで一括処理**できる。書き出しごとに待たない。
- **Studio 版はハードウェアエンコード**（NVIDIA NVENC / Apple Media Engine 等）が使えて H.264/H.265 の書き出しが大幅に速い。無料版で書き出しが遅い相談はここが原因のことがある。
- 途中で失敗する場合: 出力先の空き容量、ファイル名の禁止文字、外部ドライブのスリープ、キャッシュ破損（`Delete Render Cache` して再実行）を確認。

## 5. トラブル時の定番チェック

| 症状 | まず疑う |
| --- | --- |
| リップル削除で詰まらない | トラックの Auto Select が OFF |
| 音ズレする | 素材が VFR / プロジェクトとタイムラインのフレームレート不一致 |
| 素材がオフライン（赤） | ファイル移動。メディアプールで右クリック → `Relink Media` |
| 再生だけ映像が出ない | プロキシ／キャッシュ破損、または GPU ドライバ |
| 書き出した動画がカクつく | 再生側の問題のことが多い。別プレイヤー／別環境で確認 |
| プロジェクトが開かない・重い | プロジェクトマネージャで書き出し（.drp）してバックアップ。データベースの最適化も検討 |

> プロジェクトは **`.drp` で定期的に書き出してバックアップ**する。Resolve のプロジェクトはデータベース管理なので、ファイル1個をコピーしておけば安心、という構造ではない。
